# مسدار — موقع الطلب ولوحة التحكم

موقع طلب لمقهى مسدار: طلب محلي من الطاولة برمز QR، وسفري، ومكافآت (أختام ونقاط). ولوحة تحكم شاملة على `/admin`: كاشير للبيع المباشر، لوحة طلبات، فواتير، ورديات وصندوق، تقارير، عملاء، مخزون ووصفات، القائمة، الموظفون والصلاحيات، والربط مع هيئة الزكاة والضريبة والجمارك (المرحلة الثانية).

- الواجهة: React + Vite (تطبيق صفحة واحدة، عربي RTL).
- البيانات: Supabase (Postgres). كل منطق التسعير والمكافآت في دوال داخل القاعدة، فلا يثق الخادم بأي سعر يرسله المتصفح.
- الدفع: ميسر. التحقق من العملية يتم في دالة Netlify بالمفتاح السري.
- الاستضافة: Netlify.

## التشغيل محلياً

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # اختبارات المنطق + اختبارات قاعدة البيانات على Postgres داخل الذاكرة
npm run build
```

دون ملف `.env` يعمل الموقع في **الوضع التجريبي**: قاعدة البيانات نفسها (Postgres) تعمل داخل المتصفح، رمز الدخول `1234`، والدفع الإلكتروني زر محاكاة، ولوحة التحكم `/admin` تعرض أزرار دخول بكل دور (مالك، مدير، كاشير، باريستا). الربط مع الهيئة وإنشاء حسابات الموظفين الحقيقية لا يعملان في هذا الوضع.

## الإعداد للتشغيل الفعلي

### 1. Supabase

1. أنشئ مشروعاً في supabase.com.
2. من SQL Editor شغّل محتوى `supabase/schema.sql` كاملاً، ثم `supabase/002_admin_pos.sql` كاملاً (بالترتيب). الملف الثاني يضيف الكاشير والفواتير والورديات والمخزون والأدوار والربط مع الهيئة، ويمكن تشغيله أكثر من مرة دون ضرر.
3. أول حساب (المالك): من Authentication › Users أنشئ مستخدماً بالبريد وكلمة المرور، ثم:
   ```sql
   insert into staff (user_id) values ('معرّف-المستخدم-من-صفحة-Users');
   ```
   الموظفون المسجلون قبل تشغيل `002` يصبحون «مالك» تلقائياً. بقية الموظفين يضيفهم المالك من اللوحة › الموظفون (يحتاج متغيرات الخادم في Netlify).
4. من Settings › API Keys انسخ رابط المشروع والمفتاح العام `sb_publishable_...` والمفتاح السري `sb_secret_...`. (المفتاحان القديمان anon و service_role يعملان أيضاً، لكن Supabase ستوقفهما.)

### 2. ميسر (وضع الاختبار)

من لوحة ميسر انسخ المفتاحين التجريبيين: `pk_test_...` و `sk_test_...`. بعد صدور السجل التجاري وتفعيل الحساب تستبدلهما بمفتاحي `live` دون أي تغيير في الكود.

### 3. Netlify

اربط المستودع بموقع جديد (إعدادات البناء في `netlify.toml`)، ثم أضف المتغيرات من Site configuration › Environment variables:

| المتغير | القيمة |
| --- | --- |
| `VITE_SUPABASE_URL` | رابط المشروع |
| `VITE_SUPABASE_ANON_KEY` | المفتاح العام `sb_publishable_...` |
| `VITE_MOYASAR_PUBLISHABLE_KEY` | `pk_test_...` |
| `VITE_MOYASAR_METHODS` | `creditcard` (وأضف `stcpay` أو `applepay` بعد تفعيلهما في ميسر) |
| `VITE_SHOW_TEST_OTP` | `1` لإظهار تلميح رمز الاختبار في صفحة الدخول |
| `SUPABASE_URL` | رابط المشروع نفسه |
| `SUPABASE_SERVICE_ROLE_KEY` | المفتاح السري `sb_secret_...` |
| `MOYASAR_SECRET_KEY` | `sk_test_...` (سري) |

المتغيرات التي لا تبدأ بـ `VITE_` تبقى في الخادم ولا تصل المتصفح.

### 4. رموز الطاولات

من `/admin` › الإعدادات › رموز الطاولات: حدد عدد الطاولات واطبع. كل رمز يفتح `/t/<رقم>`، ومسحه يجعل الطلب محلياً على تلك الطاولة. اطبعها بعد ربط النطاق النهائي لأن الرابط جزء من الرمز.

### 5. الكاشير والطابعة الحرارية

- الأدوار: **المالك** كل شيء؛ **المدير** الكاشير والطلبات والاسترجاع والتقارير والقائمة والمخزون؛ **الكاشير** البيع والتحصيل والوردية والعملاء؛ **الباريستا** لوحة الطلبات ونداءات النادل.
- البيع يتطلب وردية مفتوحة بنقد افتتاحي. الدفع نقدي (مع حساب الباقي) أو شبكة أو مقسوم. كل بيع وكل تحصيل لطلب «الدفع عند الكاشير» يصدر فاتورة برقم تسلسلي، والاسترجاع يصدر إشعاراً دائناً ويعكس المكافآت والمخزون.
- الطابعة: أي طابعة حرارية 80 مم معرّفة في نظام التشغيل. الإيصال مضبوط على عرض 80 مم. لطباعة فورية بلا نافذة تأكيد على جهاز الكاشير، شغّل Chrome بهذا الخيار واجعل الطابعة الحرارية الافتراضية:
  ```
  chrome.exe --kiosk-printing https://موقعك/admin/pos
  ```
  وفعّل «طباعة الإيصال تلقائياً» أعلى صفحة الكاشير.
- المخزون: أضف المواد الخام، ثم اربطها بالأصناف في «الوصفات» ليُخصم المخزون مع كل بيع ويُعاد عند الاسترجاع.

### 6. الفاتورة الإلكترونية والربط مع الهيئة

- **المنشأة غير مسجّلة في الضريبة**: الفواتير تصدر «فاتورة» بلا ضريبة ولا تُرسل للهيئة. لا شيء مطلوب الآن.
- **عند التسجيل**: من الإعدادات فعّل «المنشأة مسجّلة في ضريبة القيمة المضافة» وأدخل الرقم الضريبي (15 رقماً يبدأ وينتهي بـ 3). الأسعار في القائمة تُعامل كشاملة للضريبة.
- **تسجيل الجهاز** (من صفحة «الربط مع الهيئة»، للمالك):
  1. ابدأ بـ «بيئة المطورين»: لا تحتاج OTP، وتفحص أن الفواتير تجتاز تحقق الهيئة. كل الخطوات يجب أن تظهر «نجح».
  2. ثم البيئة الفعلية: من بوابة fatoora.zatca.gov.sa › تسجيل وحدة حلول › توليد رمز OTP، وأدخله خلال ساعة.
- بعد التسجيل الفعلي: كل فاتورة تُوقَّع بشهادة الجهاز (ECDSA)، وتُربط بتجزئة الفاتورة السابقة، ويطبع الإيصال رمز QR الموقّع، وتُبلَّغ الهيئة تلقائياً كل 10 دقائق عبر الدالة المجدولة `zatca-cron` (المهلة النظامية 24 ساعة). «مزامنة الآن» تفعل ذلك يدوياً.
- المفتاح الخاص للجهاز يُحفظ في جدول `zatca_state` الذي لا يقرؤه إلا الخادم.
- لم يُختبر الربط بعد على خوادم الهيئة الحقيقية من بيئة التطوير؛ أول اختبار حقيقي هو تسجيل «بيئة المطورين» من اللوحة بعد النشر.

## قبل الافتتاح (مهم)

- **رمز التحقق ثابت الآن (`1234`)**: أي شخص يستطيع الدخول بأي رقم جوال. لا تنشر الموقع للعامة قبل ربط مزود SMS. الربط يتم بتعديل دالة `login_with_phone` لتتحقق من رمز يرسله المزود، أو تغيير الرمز مؤقتاً من جدول `private_settings`.
- استبدل مفاتيح ميسر التجريبية بالحقيقية.
- Apple Pay يحتاج توثيق النطاق في لوحة ميسر.

## قواعد المكافآت كما هي منفذة

- الطلب المدفوع بقيمة 6 ر.س أو أكثر (بعد خصم النقاط) يضيف ختماً. الأختام والنقاط تُضاف **بعد الدفع**: فوراً للدفع الإلكتروني، وعند ضغط الموظف «تم الدفع» أو «تم التسليم» للدفع عند الكاشير.
- بعد 3 أختام، الطلب التالي يتيح كوباً مجانياً من الأصناف المشمولة (بالحجم الأول). استخدامه يبدأ بطاقة جديدة، وذلك الطلب لا يُحتسب ختماً.
- نقطة لكل ريال مدفوع، وكل 20 نقطة تخصم ريالاً. القيم كلها تُعدَّل من لوحة التحكم.
- إلغاء طلب غير مدفوع يعيد النقاط والكوب المجاني.

## بنية المشروع

```
src/lib/pricing.ts        منطق التسعير والمكافآت (دوال نقية)
src/lib/api.ts            واجهة البيانات: Supabase إن ضُبط، وإلا الوضع التجريبي
src/lib/api.supabase.ts   التنفيذ على Supabase
src/lib/api.demo.ts       الوضع التجريبي (PGlite داخل المتصفح بالمخطط نفسه)
src/pages, src/components واجهة العميل، والإيصال (Receipt.tsx)
src/admin/                لوحة التحكم: صفحة لكل قسم
supabase/schema.sql       قاعدة البيانات الأساسية
supabase/002_admin_pos.sql الكاشير والفواتير والورديات والمخزون والأدوار والهيئة
supabase/*.test.ts        اختبارات القاعدة (PGlite)
netlify/functions/        التحقق من الدفع، إنشاء الموظفين، الربط مع الهيئة، المهمة المجدولة
netlify/zatca/            توليد XML (UBL 2.1)، التوقيع، رمز QR، طلب الشهادة، واجهة الهيئة
```

## ما لم يُنفذ بعد

التوصيل، إرسال SMS الحقيقي، الفاتورة الضريبية (B2B) للمنشآت، أجهزة الدفع المربوطة بالكاشير، إشعارات واتساب، بطاقة Apple Wallet، «اهدِ كوباً»، حجز ليالي المباريات، رف الكتب.
